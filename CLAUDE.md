# Проект

Прототип красивого блока травы в Three.js (изометрия, ортографическая камера). Код чистый, в `src`.
Старый код лежит в `архив` и не собирается, оттуда берём только идеи (см. `архив/README.md`).

Текстуры и картинки заказываем у агента Cursor, правила и шаблон запроса: `docs/textures.md`. Читать перед заказом.

# Делегирование глубокого анализа в Cursor (Grok)

Для изолированного глубокого анализа или независимого второго мнения можно вызвать Cursor CLI.
Мелкие задачи, чтение и правки кода делаем сами, без делегирования.

## Вызов (PowerShell)

```powershell
agent -p "<самодостаточная задача>" --model grok-4.7-medium --output-format text
```

- Анализ: режим только чтение, без `--force`/`--yolo`. В промпте явно писать «файлы не меняй, только отчёт».
- Генерация картинок: единственное исключение, нужен `--force --trust --workspace <public/tex>`, см. `docs/textures.md`.
- У агента нет нашего контекста: в промпте указывать файлы, вопрос и желаемый формат ответа.
- Если `agent` не найден, добавить в PATH: `$env:Path += ";$env:LOCALAPPDATA\cursor-agent"`.

## Выбор модели

| Модель | Когда |
|---|---|
| `grok-4.7-low` | быстрые вопросы, сводка по файлу, пробные вызовы |
| `grok-4.7-medium` | по умолчанию: обзор модуля, причина бага, ревью небольшого диффа |
| `grok-4.7-high` | архитектура, тонкие баги (гонки, граничные случаи), ревью крупного изменения |
| `grok-4.7-xhigh` | только по явной просьбе пользователя или при очень высокой цене ошибки |

Если пользователь указал модель или уровень, использовать его.

## Правила

- Ответ Grok — рекомендация, а не истина: перед применением перепроверять по коду.
- Не отправлять секреты, ключи и содержимое `.env`.
- Параллельно с агентом не править те же файлы.
